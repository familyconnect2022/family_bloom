FAMILY BLOOM — CHESS PHASE 14V.3C SMOOTH MOTION
Date: 2026-10-03

Goal
- Remove perceived move lag seen in one-device runtime video.
- Preserve server-authoritative move validation, clock, persistence and revision contract.

Implemented
1. Optimistic visual move layer on client.
   - Piece begins sliding immediately after the user selects a legal destination.
   - Animation duration: 145ms, native driver.
   - Input is locked while a visual move is pending.
   - Server remains authoritative; client does not commit FEN/result/clock.
2. Rollback on rejected move.
   - 110ms reverse animation restores the piece if server rejects.
3. Incoming authoritative moves animate instead of teleporting.
4. Static piece PNG assets remain local and cached by bundle.
5. Bloom Bot test think delay reduced from 700–1350ms to 250–450ms.
6. Minor/active Battle FX hold times shortened so the board is not visually obstructed for too long.
7. Temporary [ChessPerf] move:roundtrip log records real Socket/Render/Firestore ACK latency in development.

Architecture safety
- expectedRevision is still sent with each move.
- chess.js remains server-side authority.
- accepted moves are still persisted before broadcast/ACK state is used by clients.
- Optimistic layer is presentation-only and reconciles to server FEN.
