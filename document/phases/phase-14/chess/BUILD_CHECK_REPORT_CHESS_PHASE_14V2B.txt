CHESS COLD-START / FALSE-DISCONNECT HOTFIX
Date: 2026-10-03

RUNTIME EVIDENCE FROM DEVICE
- Render cold start observed at about 22 seconds.
- /health returned HTTP 200 after about 22.9 seconds.
- Socket.IO eventually emitted socket:connect and connect:ready.
- chess:lobby:join returned ok:true.
- A concurrent chess:app:join exceeded the old 12-second ACK timeout and the client incorrectly painted the lobby as a hard connection error.
- When Android reported the app leaving foreground, the global context intentionally emitted chess:app:leave and disconnected. This is correct for real background/phone-home; navigating between Family Bloom tabs must not do this.

IMPLEMENTED FIXES
1. ChessSocketService.emitAck accepts a command-specific timeout. Gameplay commands remain 12s by default.
2. app:join uses a 30s ACK window; session:getActive uses 20s; lobby:join uses 30s.
3. If app:join returns CHESS_SERVER_RECOVERING while the Socket is actually connected, the client keeps a reconnecting state and retries instead of showing a false hard error.
4. A successful lobby:join repairs connection state to ready because lobby:join performs membership/family validation too.
5. Server app/lobby join no longer blocks ACK while waiting for presence fan-out. Presence refresh runs asynchronously after room state is updated.
6. Concurrent app:join + lobby:join share one first Firestore membership read using a memberInFlight promise map; the existing 10-second membership result cache remains unchanged.
7. Temporary diagnostics now log AppState transitions and current route under [ChessDebug] so device testing can distinguish navigation inside Family Bloom from actual Android backgrounding.
8. Leaving Chess Lobby still sends lobby:leave only; it does not own or disconnect the global foreground Chess socket.
